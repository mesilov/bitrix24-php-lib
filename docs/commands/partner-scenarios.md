# Сценарии скрейпинга и обновления партнёров — техническая спецификация

## Обзор

Система работает с сайтом партнёров Bitrix24 и состоит из двух сценариев скрейпинга:

- **Сценарий `partners:scrape`** — полный парсинг всех партнёров зоны с сохранением в CSV
- **Сценарий `partners:update`** — точечное обновление конкретных партнёров по ID

Результат обоих сценариев — CSV-файл единого формата, который подаётся на вход сценарию импорта (`bitrix24:partners:import`, см. [partner-import-scenarios.md](partner-import-scenarios.md)).

---

## Общие принципы скрейпинга

Оба сценария работают с сайтом Bitrix24 и подчиняются одним правилам:

- **Зоны.** Параметр `--zone` выбирает домен Bitrix24: `ru` (Россия, дефолт), `kz` (Казахстан).
- **Задержки.** Используйте `--catalog-page-delay=2` (пауза между страницами каталога) и `--partner-detail-delay=2` (пауза между карточками партнёров). Уменьшение задержек повышает риск блокировки.
- **Обнаружение блокировки.** Сценарии автоматически определяют блокировку по пустым страницам (через `BanDetector`).
- **Один файл = одна зона.** Не смешивайте партнёров с разных зон в одном CSV.

## Сценарии использования

### Сценарий 1: Первоначальный сбор всех партнёров зоны

**Условие:** CSV файл не существует, нужен полный парсинг всех партнёров выбранной зоны.

**Действие:** Сценарий `partners:scrape` обходит все страницы каталога партнёров, скрейпит детальные карточки каждого партнёра и сохраняет результат в CSV-файл. Партнёры без детальной страницы пропускаются.

**Пример:**

```bash
# Сбор партнёров России (дефолт)
php bin/console partners:scrape

# Сбор партнёров Казахстана с ускоренными задержками
php bin/console partners:scrape --zone=kz --catalog-page-delay=1 --partner-detail-delay=1

# С кастомным выходным файлом
php bin/console partners:scrape --zone=kz --output-file=partners_kz.csv
```

---

### Сценарий 2: Возобновление прерванного парсинга (resume)

**Условие:** Предыдущий запуск `partners:scrape` был прерван (сетевая ошибка, блокировка, таймаут).

**Действие:** При обрыве создаётся state-файл `<output>.state.json` с информацией о последней обработанной странице. При запуске с `--resume` парсинг продолжится с этого места, а уже собранные данные сохраняются.

**Пример:**

```bash
# Продолжить прерванный парсинг
php bin/console partners:scrape --resume

# Продолжить с кастомным файлом
php bin/console partners:scrape --output-file=partners_kz.csv --resume
```

**Рекомендация:** При обрыве всегда используйте `--resume`, а не `--full-refresh`.

---

### Сценарий 3: Полный перезапуск парсинга (full-refresh)

**Условие:** Нужно перечитать всех партнёров с сайта и перезаписать существующий CSV-файл.

**Действие:** Сценарий `partners:scrape` с флагом `--full-refresh` игнорирует существующий CSV и начинает парсинг с первой страницы.

**Пример:**

```bash
php bin/console partners:scrape --full-refresh

# Перезапуск для Казахстана
php bin/console partners:scrape --zone=kz --output-file=partners_kz.csv --full-refresh
```

---

### Сценарий 4: Обновление конкретных партнёров по ID

**Условие:** Нужно обновить данные конкретных партнёров (например, после изменения на сайте).

**Действие:** Сценарий `partners:update` скрейпит детальные страницы только указанных партнёров и сохраняет результат в отдельный CSV-файл. Работает автономно — не требует предварительно существующего CSV. Выходной файл имеет тот же формат, что и при полной выгрузке.

**Пример:**

```bash
# Обновить двух партнёров (Россия, дефолт)
php bin/console partners:update --partner-ids=3240,5859557

# Обновить одного партнёра Казахстана
php bin/console partners:update --partner-ids=3240 --zone=kz

# С кастомным выходным файлом
php bin/console partners:update --partner-ids=3240,5859557 --output-file=partners_kz_update.csv

# Для dev-окружения
php bin/console partners:update --partner-ids=3240 --insecure
```

---

### Сценарий 5: Полный пайплайн (скрейп → импорт)

**Условие:** Нужно получить полный срез партнёров зоны и загрузить его в БД.

**Действие:** Последовательно запускаются `partners:scrape` (сбор всех партнёров) и `bitrix24:partners:import` (полная синхронизация с БД).

**Пример:**

```bash
# Шаг 1: Собрать всех партнёров Казахстана
php bin/console partners:scrape --zone=kz --output-file=partners_kz.csv

# Шаг 2: Импортировать в БД (full — CSV = источник истины)
php bin/console bitrix24:partners:import partners_kz.csv
```

---

### Сценарий 6: Точечное обновление (update → partial import)

**Условие:** Нужно обновить данные нескольких конкретных партнёров в БД без затрагивания остальных.

**Действие:** Последовательно запускаются `partners:update` (скрейп выбранных партнёров) и `bitrix24:partners:import` с `--sync-mode=partial` (только создать/обновить, остальное не трогается).

**Пример:**

```bash
# Шаг 1: Скрейпить нужных партнёров с сайта
php bin/console partners:update --partner-ids=3240,5859557 --output-file=partners_update.csv

# Шаг 2: Импортировать результат в БД (partial — не трогает остальных)
php bin/console bitrix24:partners:import partners_update.csv --sync-mode=partial
```

**Важно:** При импорте результата `partners:update` всегда используйте `--sync-mode=partial`. Иначе `--sync-mode=full` (дефолт) удалит всех партнёров, которых нет в этом файле.

## Опции сценариев

### Сценарий `partners:scrape`

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `--zone` | Зона Bitrix24: `ru`, `kz` | `ru` |
| `--output-file` | Путь к выходному CSV файлу | `partners.csv` |
| `--catalog-page-delay` | Задержка между страницами каталога (сек) | `2` |
| `--partner-detail-delay` | Задержка между карточками партнёров (сек) | `2` |
| `--insecure` | Отключить проверку SSL (для dev) | `false` |
| `--resume` | Продолжить с места обрыва (из state-файла) | `false` |
| `--full-refresh` | Перезаписать существующий файл | `false` |

### Сценарий `partners:update`

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `--partner-ids` | ID партнёров через запятую (обязательная) | — |
| `--zone` | Зона Bitrix24: `ru`, `kz` | `ru` |
| `--output-file` | Путь к выходному CSV файлу | `partners_update.csv` |
| `--partner-detail-delay` | Задержка между карточками партнёров (сек) | `2` |
| `--insecure` | Отключить проверку SSL (для dev) | `false` |

## Обнаружение блокировки

`BanDetector` отслеживает пустые страницы и определяет блокировку:

- **10+ пустых страниц подряд** — немедленная остановка
- **Более 50% пустых страниц** от общего числа — предупреждение после завершения

При блокировке увеличивайте задержки (`--catalog-page-delay`, `--partner-detail-delay`) до 2-3 секунд и повторите позже.

---

## Партнёры без детальной страницы

Если детальная страница партнёра недоступна (нет ссылки на карточку), он пропускается — не записывается в CSV. ID пропущенных партнёров выводятся в лог и в финальный отчёт. Их можно позже обновить через `partners:update`.

---

## CSV-формат

Все сценарии работают с единым форматом CSV:

```
bitrix24_partner_number,title,site,phone,email,logo_url,detail_page_url,zone,scraped_at
3240,Hoster.KZ,https://b24.kz/,8-727-2-379-284,info@b24.kz,https://.../logo.jpg,/partners/partner/3240/,kz,2026-05-01T12:27:22+00:00
```

| Колонка | Описание |
|---------|----------|
| `bitrix24_partner_number` | Уникальный номер партнёра в Bitrix24 |
| `title` | Название компании |
| `site` | Сайт компании |
| `phone` | Телефон |
| `email` | Email |
| `logo_url` | URL логотипа |
| `detail_page_url` | Относительный путь до детальной страницы |
| `zone` | Зона Bitrix24 (`ru`, `kz`) |
| `scraped_at` | Дата/время последнего скрейпинга (ISO 8601) |

**CSV-формат фиксирован** — файлы генерируются сценариями `partners:scrape` и `partners:update`.
